The digits

—
3.
 

Type any order and you get exactly that square: 100 builds a 100 × 100, 5 000 builds a 5 000 × 5 000. Nothing is stored — each cell is computed from its row and column on demand — so the order costs no memory and only the cells you can see are drawn. Order 2 is the single size with no solution.

A big square has to be shrunk to fit the page, so it is shown as a heat map until the cells are large enough to hold their digits: open it full screen to zoom in on the numbers. For a file, take the HTML — a few kilobytes at any order that rebuilds the square as you zoom, so the numbers stay real however far in you go, and it has a row, col box to jump to any cell. PNG is fixed pixels, so zooming into one only magnifies pixels; SVG carries every number as text up to order 512; and CSV gives the bare numbers up to order 2 000.

Square

—

Point at a cell to read its value. Open it full screen to zoom and pan.

Pi is computed in the page with the Chudnovsky series and binary splitting over BigInt, so the digits are generated here, not fetched. Squares use the Siamese method for odd n, the complement pattern for n ≡ 0 (mod 4), and Conway’s LUX method for n ≡ 2 (mod 4); any order from 1 to 1 024 can be typed in — that top end is 1 048 576 cells — and the construction is the same at every size. When a cell is too small for the widest number in the square the page draws a value heat map instead; the full-screen viewer re-draws the numbers as you zoom, and the SVG export carries them all as vector text. PNG and SVG exports are drawn on a white ground for printing.
